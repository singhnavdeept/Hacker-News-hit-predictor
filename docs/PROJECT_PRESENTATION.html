CI/CD Engine // Jenkins on EC2

Do We Have Jenkins on EC2? Yes, Here Is How It Works

Jenkins runs natively as an isolated container on the EC2 instance, orchestrating builds via Docker-out-of-Docker (DooD) socket sharing.

🔧 Jenkins Architecture on EC2
  • Container Name: hn-jenkins-local running jenkins/jenkins:lts-jdk17.
  • Bound Port: 0.0.0.0:8080->8080/tcp on the EC2 host.
  • Docker-in-Docker Mounting: The host's /var/run/docker.sock is mounted directly into Jenkins. This enables Jenkins to build Docker images and run test containers using the host's Docker engine.
  • Persistent Workspace: The jenkins_home volume is stored on the 20 GB EBS volume, preserving build histories across reboots.
🔑 How to Access Jenkins on EC2

1. Open the URL in your browser:

http://<YOUR_EC2_PUBLIC_IP>:8080/

2. Retrieve the initial admin password from EC2 terminal:

docker exec -it hn-jenkins-local cat /var/jenkins_home/secrets/initialAdminPassword

Once unlocked, point your Jenkins pipeline job to https://github.com/singhnavdeept/Hacker-News-hit-predictor.git to execute the 7-stage CI/CD pipeline!

Field Engineering // Troubleshooting

Operational Challenges Encountered & Overcome

Documenting real-world production engineering decisions, edge-case debugging, and system hardening on Amazon EC2.

Issue 1: Docker Build Out-Of-Memory (OOM) Crash

Symptom: SSH connection dropped abruptly during image build with client_loop: send disconnect: Connection reset.

Root Cause: EC2 t3.micro provides 1 GB RAM. Concurrently compiling models, parsing text, and extracting Docker layers consumed >950 MB, causing the Linux kernel OOM Killer to terminate SSH.

Solution: Allocated a 2 GB SSD Swapfile (/swapfile) on the EBS volume, expanding available virtual memory to 3 GB and completely eliminating memory starvation.

Issue 2: Amazon Linux 2023 Buildx Dependency

Symptom: docker compose up -d --build failed with compose build requires buildx 0.17.0 or later.

Root Cause: Amazon Linux 2023 unbundles the buildx binary from core compose packages.

Solution: Decoupled image construction using native docker build, followed by zero-rebuild composition using docker compose up -d --no-build.

Issue 3: Inbound Port 8000 Security Perimeter

Symptom: Microservice was active locally inside EC2 (curl 200 OK) but unreachable from external web browsers.

Solution: Hardened the AWS Security Group to cleanly separate Public API access (Port 8000 allowed to 0.0.0.0/0) while restricting management ports (22 SSH and 8080 Jenkins) to authorized admin CIDRs.

Issue 4: Live Container Layer Invalidation

Symptom: Browser loaded legacy API response after updating source code files.

Solution: Identified that Docker Compose preserved the 8-hour-old container due to matching service names. Implemented atomic container replacement using docker rm -f followed by tagged release rollout.
